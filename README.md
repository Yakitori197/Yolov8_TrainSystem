# 影像物件偵測與自動分檔系統

一個基於 Python 和 YOLO 的完整影像物件偵測系統，支援多攝影機即時預覽、影像標註、模型訓練以及自動分類功能。

## 功能特色

###即時預覽
- **多攝影機支援**：同時支援最多 12 台 USB 攝影機
- **即時預覽**：多攝影機畫面即時顯示（4x3 網格佈局）
- **攝影機管理**：
  - 自動檢測可用攝影機
  - 批次開啟/關閉攝影機
  - 統一同步拍照功能
  - 自動截圖（可設定時間間隔）
- **攝影機狀態監控**：即時顯示每個攝影機的連線狀態

### 標註作業
- **多格式支援**：支援 JSON（LabelMe 格式）和 YOLO 格式
- **自動轉換**：JSON ↔ YOLO 格式自動相互轉換
- **自定義類別管理**：
  - 新增/刪除物件類別
  - 預設類別：object、defect、good、bad
- **便捷標註工具**：
  - 滑鼠拖曳繪製邊界框
  - 自動建立空白標註檔
  - 批次刪除標註框
  - 圖片縮放功能
- **視覺化顯示**：即時顯示標註框和類別標籤

### 訓練模型
- **YOLO 整合**：基於 Ultralytics YOLO 框架
- **彈性設定**：
  - 自訂訓練輪數（epochs）
  - 可調整影像大小
  - 批次大小設定
  - 訓練/驗證資料集比例調整
- **訓練監控**：
  - 即時進度條顯示（百分比）
  - 訓練日誌即時輸出
  - 支援中途停止訓練
- **自動資料集準備**：自動分割訓練/驗證資料集

### 訓練結果
- **模型管理**：
  - 顯示所有已訓練模型
  - 模型檔案資訊（大小、訓練日期）
  - 重新命名模型
  - 刪除模型
  - 複製模型
- **即時辨識**：
  - 選擇任一訓練完成的模型
  - 一鍵啟用全攝影機即時辨識
  - 即時顯示偵測結果和信心度
  - 支援停止即時辨識
- **批次處理**：
  - 批次偵測整個資料夾的影像
  - 自動分類到對應類別資料夾
  - 處理進度顯示

## 系統需求

### 作業系統
- Windows 10/11
- Linux (Ubuntu 18.04+)
- macOS 10.14+

### Python 版本
- Python 3.8 或以上版本

### 硬體需求
- **CPU**：Intel Core i5 或同等級以上
- **記憶體**：8GB RAM 以上（建議 16GB）
- **GPU**：NVIDIA GPU（可選，用於加速訓練）
  - CUDA 11.0+ 支援
  - 建議 6GB 以上顯存
- **儲存空間**：10GB 以上可用空間
- **攝影機**：USB 2.0/3.0 攝影機

### 基本使用流程

1. **拍攝影像**
   - 切換到「即時預覽」頁
   - 點擊「檢測所有攝影機」
   - 點擊「開啟所有攝影機」
   - 使用「統一同步拍照」或「自動截圖」功能

2. **標註影像**
   - 切換到「標註作業」頁
   - 點擊「載入影像資料夾」選擇影像
   - 使用滑鼠拖曳繪製邊界框
   - 選擇物件類別並點擊「儲存標註」

3. **訓練模型**
   - 切換到「訓練模型」頁
   - 設定訓練參數（輪數、影像大小等）
   - 點擊「開始訓練」

4. **使用模型**
   - 切換到「訓練結果」頁
   - 選擇訓練完成的模型
   - 點擊「啟用全攝影機即時辨識」

## 詳細功能說明

### 即時預覽頁面

#### 攝影機檢測與控制
```
功能按鈕：
- 檢測所有攝影機：掃描系統中可用的 USB 攝影機
- 開啟所有攝影機：批次開啟所有檢測到的攝影機
- 關閉所有攝影機：批次關閉所有開啟的攝影機
- 統一同步拍照：同時擷取所有攝影機的當前畫面
```

#### 自動截圖功能
```
設定步驟：
1. 在「間隔(秒)」欄位輸入截圖間隔時間（預設 5 秒）
2. 點擊「開始自動截圖」
3. 系統會自動每隔指定時間擷取所有攝影機畫面
4. 點擊「停止自動截圖」結束自動截圖

影像命名格式：cam_X_YYYYMMDD_HHMMSS.png
例如：cam_0_20250128_143025.png
```

#### 攝影機狀態監控
- 綠色：攝影機正常運作中
- 紅色：攝影機連線失敗或關閉
- 顯示攝影機編號和名稱

### 標註作業頁面

#### 載入影像
```
步驟：
1. 點擊「載入影像資料夾」
2. 選擇包含影像的資料夾
3. 系統會自動載入所有支援格式的影像
```

支援的影像格式：`.png`, `.jpg`, `.jpeg`, `.bmp`, `.tif`, `.tiff`

#### 繪製標註框
```
操作方式：
1. 在影像上按住滑鼠左鍵
2. 拖曳至目標物件的對角位置
3. 放開滑鼠左鍵完成繪製
4. 從下拉選單選擇物件類別
5. 點擊「儲存標註」儲存當前標註
```

#### 標註管理
- **刪除最後一個框**：移除最近繪製的標註框
- **清除所有標註**：清空當前影像的所有標註框
- **自動建立空白標註**：為未標註的影像自動建立空標註檔

#### 類別管理
```
新增類別：
1. 點擊「新增類別」
2. 輸入新類別名稱
3. 確認後即可在下拉選單中使用

刪除類別：
1. 點擊「刪除類別」
2. 選擇要刪除的類別
3. 確認刪除（會檢查是否有標註使用該類別）
```

#### 格式轉換
- **JSON → YOLO**：將 LabelMe 格式的 JSON 標註轉換為 YOLO 格式
- **YOLO → JSON**：將 YOLO 格式的標註轉換為 JSON 格式

### 訓練模型頁面

#### 訓練參數設定
```
參數說明：
- 訓練輪數（Epochs）：模型訓練的完整週期數
  建議值：50-200（視資料量而定）
  
- 影像大小（Image Size）：訓練時的影像尺寸
  建議值：640（標準）、1280（高精度）
  
- 批次大小（Batch Size）：每次訓練的影像數量
  建議值：8-32（視記憶體而定）
  
- 訓練/驗證比例：資料集的分割比例
  預設值：0.8（80% 訓練，20% 驗證）
```

#### 開始訓練
```
訓練流程：
1. 設定訓練參數
2. 點擊「開始訓練」
3. 系統會自動：
   - 準備資料集（分割 train/val）
   - 生成 dataset.yaml 配置檔
   - 啟動 YOLO 訓練
4. 觀察訓練進度和日誌輸出
5. 訓練完成後模型會自動儲存到 models/ 目錄
```

#### 訓練監控
- **進度條**：顯示當前訓練進度（百分比）
- **日誌輸出**：即時顯示訓練過程的詳細資訊
- **停止訓練**：可隨時中止訓練過程

#### 注意事項
⚠️ 訓練時間視資料量和硬體而定，可能需要數小時
⚠️ 訓練期間請勿關閉程式
⚠️ 建議至少準備 100 張以上的標註影像

### 訓練結果頁面

#### 模型清單
顯示所有已訓練的模型，包含：
- 模型檔名
- 檔案大小
- 訓練日期時間

#### 模型管理操作
```
可用操作：
- 選擇模型：點擊清單中的模型檢視詳細資訊
- 重新命名：修改模型檔名
- 刪除模型：永久刪除模型檔案
- 複製模型：建立模型的副本
```

#### 即時辨識功能
```
啟用步驟：
1. 確保已在「即時預覽」頁開啟攝影機
2. 在模型清單中選擇要使用的模型
3. 點擊「啟用全攝影機即時辨識」
4. 切換回「即時預覽」頁觀看即時辨識結果

辨識結果顯示：
- 綠色方框：偵測到的物件
- 標籤文字：類別名稱 + 信心度百分比
```

#### 批次處理
```
使用方式：
1. 確保已載入模型
2. 點擊「批次處理＋自動分類」
3. 選擇要處理的影像資料夾
4. 系統會自動：
   - 辨識每張影像
   - 根據偵測結果分類到對應資料夾
   - 顯示處理進度
5. 完成後影像會分類到 sorted_output/ 目錄

分類邏輯：
- 有偵測到物件：依類別分類
- 未偵測到物件：歸類到 unknown 資料夾
- 多個偵測結果：選擇信心度最高的類別
```

#### 信心度閾值調整
- 使用滑桿調整偵測的信心度閾值（0.0 - 1.0）
- 較高的閾值 = 更嚴格的偵測標準
- 建議值：0.5 - 0.7

### 範例：產品瑕疵檢測

#### 場景設定
檢測產品是否有瑕疵，類別包括：`good`（良品）、`defect`（瑕疵品）

#### 步驟 1：收集影像資料
```
1. 準備至少 2 台 USB 攝影機
2. 擺放產品（良品和瑕疵品各約 50-100 個樣本）
3. 開啟程式，檢測並開啟所有攝影機
4. 使用「自動截圖」功能，設定間隔 3 秒
5. 依序擺放不同產品，系統會自動拍照
6. 收集約 200-500 張影像
```

#### 步驟 2：標註影像
```
1. 切換到「標註作業」頁
2. 設定類別：保留 good 和 defect，刪除其他類別
3. 載入 images/ 資料夾
4. 逐一標註每張影像：
   - 拖曳繪製邊界框框住產品
   - 選擇 good 或 defect 類別
   - 儲存標註
5. 使用「下一張」按鈕繼續標註
6. 完成後點擊「JSON→YOLO」轉換格式
```

#### 步驟 3：訓練模型
```
1. 切換到「訓練模型」頁
2. 設定參數：
   - 訓練輪數：100
   - 影像大小：640
   - 批次大小：16
   - 訓練比例：0.8
3. 點擊「開始訓練」
4. 等待訓練完成（約 30-60 分鐘，視硬體而定）
```

#### 步驟 4：驗證與使用
```
1. 切換到「訓練結果」頁
2. 選擇剛訓練完成的模型
3. 點擊「啟用全攝影機即時辨識」
4. 切換回「即時預覽」頁
5. 擺放新產品測試辨識效果
6. 如需批次處理舊影像：
   - 點擊「批次處理＋自動分類」
   - 選擇要處理的資料夾
   - 等待處理完成
7. 檢查 sorted_output/ 中的分類結果
```

## 常見問題

### Q1：攝影機檢測不到或無法開啟？
```
解決方法：
1. 確認攝影機已正確連接到電腦
2. 檢查其他程式是否正在使用攝影機
3. 重新插拔 USB 連接線
4. 嘗試更換 USB 插槽
5. 確認攝影機驅動程式已正確安裝
6. 在 Windows 中檢查裝置管理員
```

### Q2：訓練速度很慢怎麼辦？
```
加速方法：
1. 使用 NVIDIA GPU（需安裝 CUDA 和 cuDNN）
2. 減少訓練輪數
3. 降低影像大小（例如從 640 改為 416）
4. 減少批次大小
5. 減少訓練資料量
```

### Q3：辨識準確度不佳？
```
改善方法：
1. 增加訓練資料量（建議每類至少 100 張）
2. 提高標註品質（確保邊界框準確）
3. 增加訓練輪數
4. 確保訓練資料多樣性（不同光線、角度等）
5. 平衡各類別的資料數量
6. 使用資料增強技術
```

### Q4：記憶體不足錯誤？
```
解決方法：
1. 減少批次大小（Batch Size）
2. 降低影像大小
3. 關閉其他佔用記憶體的程式
4. 如果使用 GPU，減少 GPU 記憶體佔用
```

### Q5：標註檔案格式問題？
```
注意事項：
1. JSON 格式使用 LabelMe 標準
2. YOLO 格式：<class_id> <x_center> <y_center> <width> <height>
3. 座標值已正規化（0-1 之間）
4. 確保類別順序一致
5. 使用內建轉換工具避免格式錯誤
```

### Q6：訓練後模型找不到？
```
檢查項目：
1. 確認訓練是否成功完成
2. 查看 models/ 目錄
3. 檢查訓練日誌中是否有錯誤訊息
4. 確認有足夠的磁碟空間
```

### Q7：即時辨識沒有反應？
```
排查步驟：
1. 確認已成功載入模型
2. 確認攝影機已開啟
3. 檢查信心度閾值是否設定過高
4. 確認模型類別與實際物件匹配
5. 查看日誌輸出是否有錯誤訊息
```

### Q8：批次處理後分類不正確？
```
可能原因：
1. 模型訓練不足
2. 信心度閾值設定不當
3. 測試影像與訓練資料差異太大
4. 模型過度擬合

解決方法：
1. 調整信心度閾值
2. 增加訓練資料多樣性
3. 重新訓練模型
4. 使用更多輪數訓練
```

### 資料收集建議
1. **多樣性**：收集不同光線、角度、背景的影像
2. **數量**：每類至少 100-200 張影像
3. **平衡性**：各類別資料量盡量平衡
4. **品質**：確保影像清晰，物件完整可見

### 標註建議
1. **精確性**：邊界框盡量貼合物件邊緣
2. **一致性**：相同物件在不同影像中使用相同類別
3. **完整性**：標註影像中所有目標物件
4. **驗證**：定期檢查已標註的資料

### 訓練建議
1. **資料分割**：通常使用 70-80% 訓練，20-30% 驗證
2. **輪數設定**：從 50-100 輪開始，視效果調整
3. **過度擬合**：注意訓練損失與驗證損失的差距
4. **早停法**：若驗證損失不再下降可提前停止

### 使用建議
1. **信心度閾值**：根據實際需求調整（0.5-0.7 通常適用）
2. **模型選擇**：較新的訓練模型通常效果更好
3. **定期更新**：收集錯誤案例，重新訓練模型
4. **效能監控**：注意系統資源使用情況
